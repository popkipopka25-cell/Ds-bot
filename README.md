# 🖤 DS Bot 2.0 — управление кланом DS в Telegram

Бот ведёт состав клана, Roblox-ники, PvP-ранги, проверки, работников и **сам публикует и обновляет списки в вашей Telegram-группе**. Данные хранятся в SQLite (`ds_members.db`) и не пропадают после перезапуска.

> ⚠️ Бот должен быть запущен постоянно. Если компьютер выключен или программа закрыта, бот не отвечает, не видит выходы из группы и не обновляет списки. Для работы 24/7 нужен сервер или хостинг (см. раздел 13). После запуска бот сам догонит пропущенное: сверит состав и обновит списки.

---

## Что умеет бот

- Регистрация по Roblox-нику: проверка аккаунта через официальный Roblox API, ник обязан заканчиваться на `DS` (регистр не важен), один аккаунт — одна запись.
- Две независимые системы: **PvP-ранги** (DSa Advanced, DSe Expert, DSf Skillful, DSc Casual) и **должности** работников.
- PvP-проверки: заявка → проверяющий принимает → вносит «Мои победы» и «Его победы» → ранг рассчитывается автоматически по победам участника (0–3 DSc, 4–5 DSf, 6–7 DSe, 8–10 DSa). Матч до 10 побед, пауза 3 дня между проверками (хранится в базе и переживает перезапуск).
- Работники и индивидуальные разрешения. Менять разрешения может только владелец.
- Автоматические списки в группе (общий состав, Advanced, Expert, Skillful, Casual, работники, администрация, проверяющие PvP). Бот редактирует прежние сообщения, а если их удалили вручную, создаёт новые. Каждые 15 минут идёт сверка.
- Отслеживание выхода из группы (`chat_member`) и сверка каждые 6 часов, на случай если бот был выключен. Историю и ранги при выходе не удаляют; при возвращении запись восстанавливается после проверки Roblox-аккаунта.
- История действий, статистика, топ, поиск, резервные копии базы (каждые сутки, хранится 14 штук в папке `backups/`).

## Установка пошагово

### 1. Создайте бота в @BotFather
1. Откройте в Telegram **@BotFather** и отправьте `/newbot`.
2. Придумайте имя и username (должен заканчиваться на `bot`).

### 2. Получите токен
BotFather пришлёт строку вида `123456789:AAH...` — это **токен**. Никому его не показывайте. Если он утёк, отправьте `/revoke` в @BotFather.

### 3. Создайте Telegram-группу
Создайте группу клана (лучше **супергруппу**). Если группа уже есть, используйте её.

### 4. Добавьте бота в группу
Откройте группу → «Добавить участников» → найдите своего бота.

### 5. Выдайте боту права администратора
Группа → название → «Администраторы» → добавить бота. Включите:
- **Отправка сообщений**;
- **Удаление сообщений** (нужно, чтобы убирать лишние страницы списков);
- **Закрепление сообщений** — по желанию.

Без прав администратора бот **не получает** события о входе и выходе участников.

### 6. Укажите группу (ID вводить не нужно)
После запуска бота напишите **в группе** команду `/setgroup` **от своего имени** (не анонимным администратором). Бот запомнит группу и сразу опубликует списки.
Если хотите задать ID вручную, впишите `GROUP_ID=-100...` в `.env`.

### 7. Узнайте свой Telegram ID (владелец)
Напишите боту **@userinfobot**, он пришлёт ваш числовой ID. Он понадобится в `.env` как `OWNER_ID`.

### 8. Назначьте первых работников
Напишите своему боту `/staff` → «➕ Добавить работника» → отправьте Telegram ID или `@username` → выберите должность. Если указали `@username`, права заработают, как только человек напишет боту (достаточно `/start`). Никакой правки кода не нужно.

### 9. Установите Python
Нужен **Python 3.11 или новее**: https://www.python.org/downloads/
В Windows при установке отметьте галочку **«Add Python to PATH»**.

### 10. Установите библиотеки
Откройте терминал (в Windows — «Командная строка») в папке `DS_BOT` и выполните:

```
pip install -r requirements.txt
```

### 11. Настройте `.env`
Скопируйте `.env.example` в файл `.env` (имя ровно `.env`) и заполните:

```
BOT_TOKEN=ваш_токен_от_BotFather
OWNER_ID=ваш_числовой_ID
OWNER_USERNAME=chapapshk1
GROUP_ID=
TIMEZONE=Europe/Kyiv
```

### 12. Запустите бота

```
python bot.py
```

В терминале появится строка «Бот запущен: @имя_бота». Затем:
1. Напишите боту `/start`.
2. Напишите `/setgroup` в группе.
3. Участники пишут боту в личные сообщения и отправляют Roblox-ник.

Логи пишутся в `ds_bot.log`.

### 13. Работа 24/7
Обычный компьютер не подходит: при выключении бот перестаёт работать. Варианты:

- **VPS** (любой недорогой Linux-сервер) — самый надёжный вариант.
- **Хостинг для Python-ботов** (например, платные тарифы Railway, Render, Fly.io и похожих сервисов, где диск не стирается при перезапуске).
- Старый ПК или Raspberry Pi, которые никогда не выключаются.

> Важно: файл `ds_members.db` — это вся ваша база. Выбирайте хостинг, где диск **постоянный**, иначе после перезапуска данные пропадут. Делайте копии из папки `backups/`.

**Пример для Linux (systemd).** Создайте файл `/etc/systemd/system/dsbot.service`:

```
[Unit]
Description=DS Bot
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/home/USER/DS_BOT
ExecStart=/usr/bin/python3 /home/USER/DS_BOT/bot.py
Restart=always
RestartSec=5
User=USER

[Install]
WantedBy=multi-user.target
```

Затем:

```
sudo systemctl daemon-reload
sudo systemctl enable --now dsbot
sudo systemctl status dsbot
```

Бот будет сам запускаться после перезагрузки сервера и перезапускаться при сбоях.

## Команды

**Для всех:** `/start`, `/help`, `/profile`, `/rank`, `/rankrequest`, `/ranklist`, `/top`
**Для работников (по правам):** `/admin`, `/stats`, `/history`, `/ranks`, `/search`, `/staff`, `/pvp`
**В группе, только владелец:** `/setgroup`

Меню команд у каждого человека своё, в зависимости от прав.

## Должности и права по умолчанию

| Должность | Права |
|---|---|
| Главный администратор | участники, работники (кроме владельца), удаление, статистика, заявки, история, обновление списков |
| Администратор | участники, удаление, статистика, история |
| Модератор | нарушения, просмотр состава и профилей |
| Проверяющий PvP | просмотр и принятие заявок, внесение результатов |
| Помощник | просмотр состава, профилей, помощь участникам |
| Редактор состава | обновление списков, просмотр состава |

Владелец может включать и выключать любое отдельное разрешение: `/staff` → «Информация о работнике» → «Изменить разрешения». Работники не могут менять права себе и другим главным администраторам.

## Ограничения (честно)

1. **Roblox-ник подтверждает только то, что аккаунт существует и ник заканчивается на DS.** Бот не доказывает, что Telegram-пользователь действительно владелец аккаунта: сторонний человек может ввести чужой ник. Если это важно, проверяющий может сверять ник при PvP или можно добавить подтверждение кодом в описании профиля Roblox (доработка).
2. Telegram сообщает боту о выходе из группы только если бот **администратор**. Для пропущенных событий есть сверка раз в 6 часов.
3. Telegram не даёт боту писать человеку первым: уведомления участнику доходят, только если он хотя бы раз запускал бота (`/start`).
4. Если участник сменит ник в Roblox, бот заметит это при сверке (раз в 6 часов) и обновит запись; если новый ник не заканчивается на DS, владельцу и администраторам придёт предупреждение (автоматически участника не исключают).
5. Роль «Нарушения» у модератора — это запись нарушений в карточку участника с занесением в историю.
6. Состояние диалогов (например, ввод результата PvP на середине) хранится в памяти: после перезапуска бота диалог придётся начать заново. Данные в базе при этом не теряются.

## Структура

```
DS_BOT/
├── bot.py              запуск и регистрация обработчиков
├── config.py           настройки, должности, права
├── database.py         SQLite: схема, транзакции, резервные копии
├── roblox.py           проверка Roblox через официальный API
├── rank_system.py      таблица рангов и проверка результатов
├── pvp_system.py       заявки и результаты PvP
├── staff_system.py     работники и права
├── members_system.py   участники, профиль, топ, поиск, вход/выход из группы
├── message_manager.py  автопубликация и обновление списков
├── admin.py            панель, статистика, история
├── utils.py            общие функции оформления
├── requirements.txt
├── .env.example
├── README.md
└── backups/            резервные копии базы
```
